仍为一个 Skill、四份 reference，没有扩展 CodeVow、增加共享运行时或另建审批流程。

| 要求 | 实施边界 |
| --- | --- |
| 复用已有实现 | 新增实现前阅读相关现有代码和契约；业务含义、校验、权限/租户、事务、异常、副作用相符时复用，不只看名称或签名 |
| 同一规则抽取 | 本次多条路径表达同一规则且必须共同变化时，在最小合适位置集中维护；同类用私有 helper，跨类用适当业务归属；不建设假想通用框架 |
| 不同语义独立 | 外观相似但业务独立演进的实现保持独立；可以复用真正通用的校验，不用布尔模式把不同业务拼成万能方法 |
| 内部类尽量避免 | 业务 DTO、结果、策略、Spring 组件优先顶级类型，保持必要可见性；覆盖非静态内部类、静态嵌套类及嵌套 record/枚举/接口 |
| 保留必要嵌套 | 需要具体封装或框架/测试理由；private、短、单个调用方、省文件都不能单独证明必要；不借此迁移无关历史类型或破坏既有 API、装配和序列化 |

这是用户维护性偏好，不声称 Java 或 Spring 禁止嵌套类型。已核对
[Java 17 嵌套类规范](https://docs.oracle.com/javase/specs/jls/se17/html/jls-8.html#jls-8.1.3)
与 [Spring 类型独立性说明](https://docs.spring.io/spring-framework/docs/current/javadoc-api/org/springframework/core/type/ClassMetadata.html#isIndependent())。
本轮不执行 Spring 容器或声明其装配通过。

## 2. 反例与冻结判定

新增 [R25—R29](../../plugins/ai-code-stack-standards/evals/cases.md)，五个 Java 17 无依赖小项目。
仅 seed 进入临时候选工作区；oracle、检查器和操作员判断留在外部。

| 场景 | 行为验证 | 独立结构判断 |
| --- | --- | --- |
| R25 已有配送费实现 | 原始政策与临时替换后的政策都必须由两个入口跟随；相同初值的复制实现会失败 | 实际调用已有业务政策，没有额外平行实现 |
| R26 同一会员优惠规则 | 两入口边界与异常正确；另在临时副本中只改实际归属点一次，两个入口必须同时改变 | 检查真实调用和归属，拒绝双副本及多余框架，不按方法名或行数判抽取 |
| R27 取消与退款规则独立 | 合法/非法输入正确；单独替换订单入口后退款行为保持；该试验不覆盖所有内部耦合 | 审阅业务政策是否独立，允许通用校验复用，拒绝跨域委托和无必要布尔模式 |
| R28 新增业务报价结果 | 原费用、距离边界、非法输入和结构化结果正确；自动判定故意接受顶级和嵌套两种正确形态 | 默认顶级业务类型；必要性和位置以实际 diff 判断，不把功能通过等同于结构合适 |
| R29 既有 JDK 迭代器修复 | 末项、空集合、快照、独立游标、耗尽异常、只读性和公开成员保持 | 允许有具体状态封装理由的局部实现或更简 JDK 方案，不强制拆类、暴露状态或扩大 API |

两组外部校准分别 **12 项**，均符合预定结果：缺失实现、旧政策、漏校验、复制政策、
错误费用/天数、共享游标和状态泄露等以实际语义断言失败；正确实现通过。
所有起始缺陷先能够编译，没有把缺环境或工具故障当作 RED。

校准刻意包含以下“功能通过但结构不能因此合格”的控制：

- R26 双副本普通行为通过；只改一个副本后传播检查失败。
- R27 布尔万能方法仍可通过行为和入口替换，必须由实际 diff 审阅拒绝。
- R28 正确顶级及嵌套结果都通过功能检查，结构另判。

手工正向控制不计为模型成功，自动检查器不充当技术栈或抽象分类器。
