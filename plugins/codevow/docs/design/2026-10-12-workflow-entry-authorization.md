# 工作流入口与分析转开发的授权检查

日期：2026-10-12。范围：用户确认的入口触发、按需读取和授权转换修订。
本记录补充 2026-10-01 验收矩阵与 2026-10-03 轻量约束设计，保留其历史正文。

## 行为与资源范围

保留六技能与现有策略、任务数据契约、管理工具接口。`workflow` 维护唯一完整
请求与授权契约；其余五技能在专项步骤前链接该契约，直接调用时也先核对上下文。
技能 description 表达适用节点；Codex 界面提示与插件入口一致，保持自动选用可用。
公开双语使用指南和随包说明提供用户主动接入项目指令的短入口，不自动修改项目
指令、全局配置或安装缓存，不新增运行时、hook 或 approved 授权标记。

调查、排查和独立审查发现缺陷后报告证据、影响、建议与验证范围，不能自行写测试
或修复。默认协作模式等待适用方案确认；已有范围内继续推进，问句不会撤销有效
授权，明确停止或限制仍须遵守。测试限定授权不会扩展为业务源码修复。
未修复严重缺陷阻塞相关开发交付，不阻止只读调查或审查完成。

## 执行与判定边界

使用 `evals/prepare.py` 生成一次性 fixture；运行前记下真实宿主、模型、包哈希、
策略来源与工作区文件/目录基线。按场景顺序逐轮发送用户内容；多轮场景必须保留
每轮输出和工具边界，不能把确认或后续问句提前并入第一轮。

自动触发场景不手动预读技能，不给模型预期答案或额外“不要修改”的提示。
直接调用场景按原请求调用指定技能，验证共同入口的实际读取或已存在有效上下文。
项目入口接入与仅安装插件分别记录，不能把显式加载成功称为自动选用成功。
命令观察须避免产生未授权的 pycache 等 fixture 文件；检查整个目录树，不只检查
业务源码。代码修复场景须验证 RED/GREEN、正常/异常路径及新增文件范围。

在声明的 Claude Code、Codex、ZCode 中分别执行关键场景至少三次，用原生导出
或有原始材料支撑的注释记录技能加载、用户确认、写入顺序、最终 diff 和结论。
`collect`/`grade` 的 agent 语义继续要求真实材料审核；没有会话材料时维持
`not_run`、`manual_review` 或实际环境阻塞，静态通过不得改写为宿主通过。

结构回归检查覆盖共同入口引用、链接 anchor、原生入口提示一致性及全部新增场景
的真实 prepare/基线绑定。它们证明源码连接与验收准备可运行，不证明模型行为。
