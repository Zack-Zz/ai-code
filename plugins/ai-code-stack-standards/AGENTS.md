# CodeStack maintenance

Read the repository AGENTS.md before changing this plugin.

- Keep one English `code-standards` skill and only the approved English rule references; do not add empty language or framework placeholders.
- Preserve the approved Java, data-access, JPA and MyBatis boundaries and the user's explicit comment, test-construction and query requirements. Frontend rules are shared across frameworks and apply to affected copy in products with existing or explicitly requested multilingual support.
- Keep multilingual frontend copy in a dedicated, centrally maintained resource area, referenced by keys. This is an explicitly adopted project convention; do not claim measured model improvement without evidence.
- Keep project detection instruction-based. Do not add a runtime classifier, hooks, agents, project configuration or installation code.
- Test meaningful package and discovery behavior. Static contracts do not prove LLM routing or native host behavior.
- Keep evaluation fixtures anonymous, local and outside the package resource allowlist. Deliberately flawed fixture code is evaluation input, not a recommended implementation.
- Changes to behavior require a valid failing test or recorded behavioral failure before the corresponding fix. Plain documentation uses proportionate structural checks.
- Native loading, implicit selection and task outcomes need separate evidence; retain pending status when unavailable.
- Do not commit, push, tag, install, publish or change global host configuration in this task.
